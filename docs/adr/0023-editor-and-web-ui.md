# ADR-0023: Рабочая копия в редакторе и `jarvis ui` — локальный веб-интерфейс поверх журнала

- Статус: принято; §2–§5 сделаны (§6, пп. 1–6); расширение IDE (§6, п. 5) — по итогам пилота. Это «отдельное решение» о GUI, которое откладывал
  [ADR-0018](0018-terminal-observability.md); терминал остаётся главным интерфейсом ([ADR-0022](0022-terminal-interface.md))
- Дата: 2026-10-06
- Основание: [ADR-0022](0022-terminal-interface.md) §9 (всё, что видно, выводится из журнала событий),
  [ADR-0018](0018-terminal-observability.md) §2 (UI — читатель БД и потока событий, действия — те же
  команды с актором), [ADR-0019](0019-human-collaboration.md) §5–§6 (замечания к строкам, ручные правки
  как checkpoint), [ADR-0003](0003-workspace-worktree.md) (worktree на прогон), [ADR-0006](0006-actor-identity.md)
  (актор решения), [ADR-0010](0010-secret-redaction.md) (что можно показывать); пилот
- Код: `src/cli/checkout.ts` (`editorFor`, `systemOpener`, `watchCheckout`), `src/cli/gate.ts` (`o`, живая
  строка `changed`), `jarvis open` в `src/cli/commands/run.ts`; план — `src/ui/{server,pages,events}.ts`,
  `src/cli/commands/ui.ts`
- Макеты: холст «Jarvis: open in IDE + web UI» (анимация `o`, страницы runs, run, review)

## Контекст

Пилот показал, где терминал перестаёт помогать:

1. **Правка руками.** Петля verify → implementation исчерпалась на мелочах (перевод строки в конце файла,
   пробные файлы). Исправить — минута, но «fix it there yourself» отправлял человека копировать путь из
   хэшей, а шелл из карточки уводил из процесса: назад вёл только `exit`, о котором никто не догадывался.
   Править код — работа для IDE, а не для терминала.
2. **Чтение и решение.** Спека, impact, дифф реализации, замечание к конкретной строке. В терминале это
   пейджер и `$EDITOR` — терпимо, но дифф бок о бок, комментарии на строках и переходы между артефактами
   в браузере объективно удобнее.
3. **Несколько прогонов сразу.** `status` и `follow` по вкладкам терминала не масштабируются.

При этом ход прогона — живые строки, ожидание модели, Ctrl-C, CI, tmux — терминал показывает хорошо.

## Решение

### 1. Терминал ведёт, остальное — окна над тем же журналом

Прогон запускает и ведёт терминал (`work`, `continue`, `fix`). Редактор и браузер — дополнительные окна:
редактор — для правки рабочей копии, браузер — для чтения, ревью и решений. Ни одно окно не хранит своего
состояния: всё берётся из журнала событий, артефактов и рабочей копии; решение из любого окна
записывается одной и той же функцией приложения (`recordDecision`, повтор шага — `resume`), с актором.

### 2. `o` — рабочая копия в редакторе (сделано)

- На карточке исчерпанной петли и на гейте прогона с собственной рабочей копией (worktree) клавиша `o`
  открывает её в редакторе человека, не дожидаясь его закрытия; `jarvis open [run]` — то же из любого места.
- Редактор: `JARVIS_EDITOR` (команда, можно с аргументами: `idea`, `code -n`), иначе первая известная
  команда на PATH (`code`, `cursor`, `webstorm`, `idea`, `zed`, `subl`), на macOS — установленное
  приложение через `open -a`, иначе файловый менеджер. `$EDITOR`/`$VISUAL` для этого не годятся: это
  обычно терминальный редактор для текста комментария (§4 ADR-0022).
- Карточка остаётся на месте и **следит за рабочей копией** (`git status` раз в 1,5 с): новые изменения
  появляются строкой `changed  D tmp-a.txt  M …/a.test.ts · r runs verify again with them` над вопросом,
  без нажатий. `r` делает правку ручным checkpoint (ADR-0019 §6) и запускает шаг новым кругом.
- Шелл (`s`) остаётся запасным путём: он закрывается сам, когда в нём набирают привычное `jarvis c`.

### 3. `jarvis ui` — локальная страница

`jarvis ui [--port N] [--open]` поднимает HTTP-сервер на `127.0.0.1` и (с `--open`) открывает браузер.
Страницы:

| Страница | Содержание |
| --- | --- |
| Runs | ждущие человека — сверху, с причиной и кнопкой; идущие — шаг, активность, бюджет инструментов; недавние — состояние, время, вызовы модели |
| Run | шаги с итерациями и вложенными этапами composite, петли, живая активность; карточка решения того же вида, что в терминале: причины, рабочая копия, «Open in editor», живые изменения, «Run verify again» |
| Review | артефакт: сводка, требования, риски; для реализации — дифф по файлам с комментариями к строкам; «Accept» / «Send back with N comments» |

Комментарии к строкам уходят в возврат так же, как маркеры Review Mode (ADR-0019 §5): `путь:строка —
текст`, одним комментарием к `request_changes`.

### 4. Терминал подхватывает решение из браузера

Карточка в терминале, пока ждёт ответа, следит не только за рабочей копией, но и за прогоном: появилось
решение по ожидаемому артефакту (`approval.recorded`) или прогон сдвинулся с места — карточка пишет
`✓ accepted in the browser by <актор>` и идёт дальше, как после своей клавиши. Наоборот, браузер видит
решения из терминала через тот же журнал. Двух решений по одной версии быть не должно: `recordDecision`
отвергает второе («версия уже решена») — проверка добавляется на этапе 2 (§6).

Сделано так (этап 2, §6):

- Карточка (гейт одобрения и исчерпанная петля) раз в секунду смотрит журнал: `approval.recorded` по
  ожидаемой версии, `loop.rerun` («Run again» со страницы) после последней остановки, состояние прогона.
  Вопрос, ждущий клавишу, снимается (`Prompt.ask` с `AbortSignal`); строка, набранная уже после этого, не
  читается следующим вопросом — так клавиша для ушедшей карточки не решит следующую.
- Решение при прогоне, который всё ещё ждёт, подхватывается со второго взгляда (через секунду): если его
  записали с `--resume`, тот процесс успевает взять аренду, и терминал не соревнуется с ним за неё.
- Прогон, который продолжил другой процесс, терминал не перехватывает (ADR-0002 §5): он следит за ним, как
  `jarvis follow`, и снова показывает карточку, если прогон остановится ради человека. Если аренду всё же
  взял другой процесс на мгновение раньше (`LeaseHeldError` после карточки), терминал тоже переходит к
  слежению.
- Решение, принятое до того, как открылась карточка, не спрашивается второй раз.
- `recordDecision` отвергает второе решение по той же версии (`DecisionTakenError`: кто и как уже решил);
  у `approval.recorded` — `channel` (`cli`/`ui`).
- Карточка отмечает в журнале, что ждёт (`card.open`/`card.closed` с pid): страница знает, пойдёт ли прогон
  дальше сразу после решения или будет ждать `jarvis continue`.

### 5. Устройство и безопасность

- `node:http` без фреймворка; страницы — HTML, который отдаёт сервер, плюс небольшой скрипт без сборки;
  живые обновления — Server-Sent Events из хвоста `events` (polling БД раз в секунду, как `follow`).
  Без React и без шага сборки: тот же довод, что против Ink в ADR-0022.
- Только `127.0.0.1`. Адрес содержит случайный токен сессии (`/?t=…`), без него — 403; действия — `POST`
  с этим токеном, чтобы чужая страница в том же браузере не могла их вызвать.
- Показывается то же, что терминал: артефакты и выдержки после редакции секретов (ADR-0010); сырые
  ответы модели и переменные окружения — нет. Наружу сервер ничего не отправляет.
- Актор действий — тот же, что у CLI на этой машине (ADR-0006); у записи решения `channel: ui`.

### 6. Порядок

1. Сделано: `o`, `jarvis open`, живая строка `changed` (§2).
2. Сделано: терминал подхватывает решение, принятое вне него (§4) — нужно и без веб-страницы
   (`jarvis approve` из другой вкладки).
3. Сделано: `jarvis ui`: Runs, Run и страница артефакта (документ, дифф реализации) только для чтения,
   SSE. Код — `src/ui/{server,model,pages,html,assets}.ts`, `src/cli/commands/ui.ts`; страницы строятся
   из тех же `Journey`, `activityOf`, `reasonsOf`, `docFacts` (сводка гейта), `changesIn`, что и
   терминал. Markdown и дифф превращаются в HTML своим небольшим рендерером: всё экранируется, ссылки —
   только http(s). Токен — в адресе один раз, дальше — cookie `HttpOnly; SameSite=Strict`; `Host`
   проверяется (DNS rebinding); CSP запрещает встроенные скрипты, `Referrer-Policy: same-origin` (адрес не уходит к шрифтам).
4. Сделано: действия — Accept / Send back (с комментариями к строкам диффа `путь:строка — текст`), Run
   again, Open in editor. `POST` с токеном сессии в форме и проверкой `Origin`; решение — `recordDecision`
   с актором CLI и `channel: ui`, «Run again» — событие `loop.rerun` (`requestRerun`). Сервер не
   продолжает прогон сам: карточка, ждущая в терминале (`card.open`), подхватывает решение (§4); без неё
   страница предлагает `jarvis continue <run>`, и карточка не спрашивает второй раз (решение уже есть,
   «Run again» уже попрошен). Запускать отделённый `jarvis resume` из сервера не стали: прогон без
   терминала шёл бы невидимо, а его остановки ради человека никто бы не увидел, кроме страницы.
5. Сделано: **New task** на странице. Сервер по-прежнему не исполняет workflow в себе и не держит аренду:
   он запускает тот же CLI, что набрал бы человек (`jarvis fix "…"`), отделённым процессом без терминала,
   вывод — в файл (`src/ui/launcher.ts`). Такой прогон помечается `run.driver {by: ui}` и **ведётся
   страницей**: после решения на странице (или «Run again») сервер запускает `jarvis resume <run>` в фоне,
   а прогон, ждущий модель или окно квоты, — когда ожидание кончилось. Довод п. 4 против фонового
   `resume` здесь не работает: прогон начат на странице, и его остановки видны там же. Прогоны, начатые в
   терминале, остаются за терминалом.
6. Сделано: `jarvis forget` — законченные прогоны уходят из хранилища (после эксперимента — чистый лист).
7. По итогам пилота — расширение для IDE с теми же страницами, если браузер окажется лишним окном.

## Последствия

- У каждого действия три входа — клавиша на карточке, кнопка на странице, команда для скриптов, — и одна
  функция за ними; новое действие добавляется во все три.
- Карточки в терминале перестают быть «ждущими ввода»: они следят за журналом и рабочей копией.
- Страницы — ещё одна поверхность вывода под тестами: снимки HTML страниц из тех же структур, что и строки
  терминала (`Journey`, `activityOf`, `runDetail`).
- Появляется процесс-сервер; он не исполняет прогоны и не держит аренду (ADR-0002), только читает и
  записывает решения.

## Альтернативы

- **Только терминал (ADR-0018 в исходном виде).** Не решает правку руками и ревью дифа с комментариями.
- **Полноэкранный TUI (Ink, lazygit-подобный).** Навигация по прогонам лучше, но дифф и комментарии к
  строкам остаются неудобными, и теряется история терминала (ADR-0022 §1).
- **Отдельное приложение (Electron, Tauri).** Сборка, обновления, подпись — много цены за окно, которое
  браузер даёт бесплатно.
- **Расширение IDE сразу.** Ближе всего к правке, но два разных API (VS Code, JetBrains) и привязка к
  редактору; разумно после того, как страницы докажут ценность (§6, п. 5).
- **Шелл из карточки как главный путь правки.** Сделан и оставлен запасным: в пилоте он уводил из
  процесса, а правят люди всё равно в IDE.
