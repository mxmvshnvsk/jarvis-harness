# ADR-0008: Инкрементальный Project Graph

- Статус: принято
- Дата: 2026-10-03
- Основание: [ADR-0001](0001-target-architecture.md) §8 (Project Graph на TypeScript Compiler API / ts-morph /
  git, «детерминированный индекс»), §15 (pre-push: сначала детерминированный impact по diff), §17 (ripgrep,
  git, ts-morph), §21 («pre-push/CI сначала используют детерминистический анализ»); [ADR-0003](0003-workspace-worktree.md)
  §6 (кэш общий для worktree)
- Код (план): `src/knowledge/graph/{extract,resolve,snapshot,cache}.ts`, экстракторы
  `src/knowledge/graph/extractors/{ts,routes,tests,events}.ts`, таблицы `graph_*` в SQLite, CLI
  `jarvis knowledge update|status`

## Контекст

Project Graph строится ts-morph'ом над «сложным legacy». Полный проход по большому TypeScript/React
репозиторию — минуты и гигабайты памяти. Если `jarvis prepush` и impact analysis ждут полного пересчёта,
хук отключат в первую неделю, а impact в CI станет самым медленным шагом pipeline. ADR-0001 требует
детерминированности индекса, но не говорит, как он остаётся дешёвым при изменении одного файла.

## Решение

### 1. Два уровня: факты по файлу и граф по дереву

**Факты по файлу** — чистая функция содержимого файла и конфигурации (`tsconfig` hash, версия экстрактора):
объявленные символы, экспорты, импорты (сырые спецификаторы), JSX-компоненты, роуты, тестовые ссылки,
события/метрики. Ключ кэша — `(extractorVersion, configHash, blobSha)`; хранится content-addressed в
`~/.jarvis/cache/graph/<repoId>/blobs/<sha>.json`. Blob sha одинаков во всех ветках и worktree, где файл не
менялся, — кэш общий.

**Граф по дереву** — разрешение импортов в рёбра (`tsconfig paths`, barrel-файлы, алиасы), построение
зависимостей, тестов и «кто использует». Ключ — `(repoId, treeSha)`. Хранится в SQLite (`graph_snapshots`,
`graph_nodes`, `graph_edges` с `snapshot_id`), с последним снимком на ветку.

### 2. Инкрементальное обновление

`jarvis knowledge update` (вызывается prepush, impact-шагом и daemon'ом):

1. `git diff --name-status <lastSnapshot.treeSha> <HEAD-tree>` — список изменённых файлов;
2. для изменённых — пересчёт фактов (с попаданием в blob-кэш, если файл уже встречался в другой ветке);
3. пересчёт рёбер только для изменённых файлов и их прямых зависимых (обратные рёбра из снимка); остальные
   рёбра копируются ссылкой на предыдущий снимок;
4. новый снимок помечается `treeSha`; старые снимки удаляются по retention (последние 5 на ветку).

ts-morph `Project` создаётся только над изменёнными файлами и их прямыми зависимыми; полный typecheck не
нужен для графа. Там, где требуются ошибки типов (verification-шаг), используется `tsc --incremental` с
`.tsbuildinfo` в кэше worktree.

### 3. Детерминированность

Экстракторы сортируют выход, не используют время и случайность; `jarvis knowledge status --verify`
пересчитывает снимок с нуля и сверяет хэш — это тест на детерминированность, прогоняется в CI на fixture-
репозиториях.

### 4. Бюджеты времени и деградация

| Ситуация | Поведение |
| --- | --- |
| Тёплый кэш, типичный diff | обновление ≤ 5 с (целевой SLO, измеряется в telemetry `graph.update`) |
| Холодный кэш в prepush | не блокировать: impact по лексическому поиску (ripgrep) с предупреждением «graph cold»; полная индексация запускается в фоне daemon'ом или `jarvis knowledge update --full` |
| Холодный кэш в CI | восстановление `cache/graph` из CI-кэша по ключу `treeSha` ближайшего предка; иначе полная индексация в рамках job, без деградации |
| Файл не парсится | факт с `error`, узел в графе есть, рёбер нет; impact помечает область как «неизвестно» |

### 5. Экстракторы — плагины с тем же кэшем

TS/TSX — базовый. Роуты (React Router/Next), OpenAPI/YAML-контракты, события аналитики, feature-flags —
отдельные экстракторы с тем же интерфейсом `(blob, config) → facts` и тем же blob-кэшем. Семантические
связи от LLM (ADR-0001 §8) — отдельный слой поверх снимка, в сам снимок не пишутся.

### 6. Чего нет сейчас

Watch-режим по fs-событиям — позже, через daemon, когда появится измеримая потребность. Sparse/partial
индексация монорепозитория по пакетам — по мере необходимости; архитектура (факты по blob) её не исключает.

## Последствия

- `prepush` остаётся быстрым и никогда не блокирует на холодном кэше — условие выживания хука.
- Один blob-кэш на все ветки и worktree; переключение ветки почти бесплатно.
- CI получает воспроизводимый индекс и может кэшировать его по `treeSha`.
- Цена — два уровня кэша и логика инвалидации; покрывается `--verify` и fixture-репозиториями.

## Альтернативы

- **Полный пересчёт при каждом вызове.** Прост, но непригоден для хуков на большом репозитории.
- **Language Server (tsserver) как источник графа.** Хорош интерактивно, плохо воспроизводим в CI, тяжёлый
  процесс для daemon'а; не даёт content-addressed кэша.
- **Внешние индексаторы (SCIP/LSIF).** Рассмотреть позже как экстрактор, если собственный TS-экстрактор
  окажется узким местом; формат снимка это допускает.
