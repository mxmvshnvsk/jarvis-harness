# ADR-0014: Приоритет конфигурации и версионирование схем (БД, артефакты, конфиг, бандлы)

- Статус: принято
- Дата: 2026-10-03
- Основание: [ADR-0001](0001-target-architecture.md) §3 (`~/.jarvis/config.yaml`, `.jarvis/project.yaml`,
  `jarvis.db`), §12 (`schemaVersion` артефакта), §15 (`jarvis doctor`), §17 (Config: YAML + Zod);
  [ADR-0009](0009-ci-mode-and-human-gate.md) §1 (профили) и §5 (бандлы), [ADR-0010](0010-secret-redaction.md)
  (секреты не в yaml)
- Код (план): `src/core/config/{schema,load,resolve,show}.ts`, `src/storage/migrations/*.sql`,
  `src/storage/migrate.ts`, `src/artifacts/schemas/<type>/v<N>.ts`, CLI `jarvis config show --sources`,
  `jarvis doctor`, `jarvis db migrate|backup`

## Контекст

У Jarvis четыре источника настроек (встроенные дефолты, пользовательский конфиг, проектный конфиг,
окружение/флаги) и профили поверх них. Без зафиксированного порядка «почему он взял эту модель» —
загадка. У `jarvis.db` нет версии схемы, у артефактов она есть, у конфига и бандлов — не определена. Пакет
обновляется чаще, чем проекты и локальные базы; без миграций обновление — потеря runs.

## Решение

### 1. Приоритет конфигурации

По убыванию: CLI-флаги → env `JARVIS_*` (`JARVIS_MODELS__DEEPSEEK_FLASH__ENDPOINT`, разделитель `__`) →
`.jarvis/project.yaml` → `~/.jarvis/config.yaml` → встроенные дефолты. Результат — один объект, проверенный
Zod-схемой целиком (ошибка указывает ключ и источник). Профили (`profiles.<name>`, ADR-0009) — наложение на
уже разрешённый объект, выбранное флагом `--profile` или автоматически (`ci` при `actor.kind = ci`);
профиль может только сужать права (валидация отвергает расширение).

Секреты в yaml запрещены схемой: поля credentials принимают только ссылки `env:VAR` или `keychain:<id>`;
литерал — ошибка загрузки.

### 2. `jarvis config show --sources`

Печатает каждый ключ с источником и, для переопределённых, цепочку значений — по образцу `git config
--show-origin`. Это основной инструмент `doctor` и ответа на «почему он так сделал».

### 3. Версии везде

| Что | Поле | Где |
| --- | --- | --- |
| `jarvis.db` | таблица `schema_migrations (version, applied_at, package_version)` | SQLite |
| артефакты | `schemaVersion` на тип (ADR-0001 §12) | метаданные артефакта |
| конфиг | `version: 1` первой строкой | оба yaml |
| бандлы | `bundleVersion` + версии всех включённых схем | манифест бандла |
| кассеты evals | `cassetteVersion` | заголовок файла |

Правило: пакет знает диапазон поддерживаемых версий каждой схемы. Старее — миграция вперёд; новее —
отказ с сообщением «обновите jarvis до ≥ X», без попытки частично прочитать.

### 4. Миграции БД

Forward-only SQL-миграции в пакете (`NNNN_<name>.sql`), применяются при открытии БД в транзакции под
эксклюзивной блокировкой (`BEGIN IMMEDIATE`), перед этим — копия файла `jarvis.db.bak-<version>` (хранится
одна предыдущая). Запуск с БД, у которой есть неизвестные миграции, — отказ (§3). Отката нет: откат — это
восстановление `.bak` и старый пакет. Daemon и CLI разных версий на одной БД — отказ младшего.

### 5. Миграции артефактов и бандлов

Артефакты не переписываются: чтение версии `v<N>` идёт через `upcast` к текущей схеме в памяти
(`src/artifacts/schemas/<type>/upcast.ts`), запись — всегда в текущей. Бандл при импорте проверяется по
манифесту; артефакты в нём читаются тем же `upcast`. Для конфига — `jarvis config migrate` переписывает yaml
с сохранением комментариев там, где это возможно, и показывает diff.

### 6. `jarvis doctor`

Проверяет: версию схемы БД и наличие `.bak`; версию конфигов и ошибки схемы с источниками; дескрипторы
моделей и свежесть probe (ADR-0007); актора (ADR-0006); чистоту worktree после `workspace.setup`
(ADR-0003); статистику редакций (ADR-0010); состояние кэша графа (ADR-0008). Каждая проверка — код и
подсказка.

## Последствия

- Любое значение конфигурации объяснимо одним вызовом.
- Обновление пакета безопасно для локальных данных; «новее, чем знаю» никогда не читается частично.
- Цена — дисциплина: каждое изменение схемы сопровождается миграцией или `upcast` и тестом на фикстуре
  предыдущей версии.

## Альтернативы

- **Один конфиг без приоритетов.** Не работает с CI и личными переопределениями.
- **ORM-миграции с откатом.** Откат схемы с данными ненадёжен; `.bak` + forward-only проще и честнее.
- **Переписывать старые артефакты при миграции.** Нарушает неизменяемость версий (ADR-0005).
