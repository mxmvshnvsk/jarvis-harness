# Knowledge в `jarvis ui`: база знаний в браузере — предложение

- Статус: **закрыто**. Сделанное (исследование модуля §8, просмотр знаний и глоссарий §9) закреплено в
  [ADR-0024](../adr/0024-knowledge-in-web-ui.md); правку в браузере и «принести новое» не делаем — там же,
  «Чего не делаем». Ниже — исходное предложение, как было.
- Дата: 2026-10-07
- Основание: [ADR-0023](../adr/0023-editor-and-web-ui.md) (`jarvis ui`: страница — окно над теми же данными,
  действия — те же функции, что у CLI), [ADR-0020](../adr/0020-skills-and-standards.md) (стандарты, навыки,
  кандидаты в знание), [ADR-0015](../adr/0015-semantic-retrieval.md) (поиск и глоссарий), [ADR-0008](../adr/0008-incremental-project-graph.md)
  и [ADR-0021](../adr/0021-stack-agnostic-core.md) (граф проекта), [knowledge.md](../knowledge.md) (виды знания и
  их форматы), [ADR-0010](../adr/0010-secret-redaction.md) (редакция секретов)
- Макеты: холст «Jarvis: open in IDE + web UI», ряд 3 «Knowledge» — обзор, глоссарий, «принести новое»,
  документ, стандарт

## Контекст

Знание проекта уже есть и работает: документы `.jarvis/knowledge/*.md`, глоссарий
`.jarvis/knowledge/glossary.md`, стандарты `.jarvis/standards/`, навыки `.jarvis/skills/`, внешняя
документация команды через `knowledge.sources`, кандидаты из ревью (`jarvis candidates`). Но наполнять и
поддерживать его неудобно:

- правка — руками в редакторе, без подсказок: опечатка в символе глоссария или `paths`, которые ничему не
  соответствуют, видны только по плохой работе агентов;
- непонятно, **найдёт ли агент** то, что написано, — поиск с расширением глоссарием невидим;
- непонятно, **где дыры**: какие модули не описаны, какие документы отстали от кода;
- принести знание извне (страница Confluence, заметка, описание процесса) — значит самому разложить его на
  документ, термины и правила;
- стандарт с `severity: required` можно написать так, что он завалит каждый прогон, и узнать это только в
  прогоне.

## Предлагаемое решение

### 1. Правда — файлы репозитория

Страница — редактор над теми же файлами, нового хранилища нет. Изменения идут через git: команда видит их в
PR, история — в `git log`. Внешние `knowledge.sources` (например, `documentation/`) на странице видны, но
**только для чтения**: у них свой владелец.

### 2. Страницы

Пункт **Knowledge** в шапке `jarvis ui`, рядом с Runs.

| Страница | Что на ней |
| --- | --- |
| Обзор | счётчики (документы, стандарты, навыки, термины, источники); «Найдёт ли агент?» — строка поиска как у агентов с трассой расширений глоссария и найденными единицами, рядом `jarvis ask`; термина нет — «добавить в глоссарий?»; покрытие модулей графа (документ, навык, только заготовка, ничего — «описать» через `onboard --module`); «может устареть»; входящие кандидаты; полоса черновиков |
| Глоссарий | таблица с правкой в строке; при правке символы сверяются с графом (✓ найден, ? не найден — «может, `X`?»); подсветка проблем: символа больше нет в коде, синоним занят двумя терминами; фильтр «только проблемы»; панель «где встречается»: во что раскрывается запрос, какие документы и файлы находятся |
| Принести новое | текст / ссылка (Confluence через MCP) / файл и источник; агент раскладывает на предложения с evidence: новый документ (с `paths`, найденными по терминам, и превью), термины, кандидаты в стандарты (цитата-основание), **конфликты** с существующим знанием (что делать: обновить старое, оставить оба с пометкой «устарело», спросить команду); принятие по пунктам |
| Документ | дерево документов (источники — только чтение); markdown: Write / Preview / Changes; front matter формой: теги, `paths` с автодополнением по модулям графа и числом файлов, агенты; как индекс порежет документ на единицы и предупреждение о почти пустых разделах; плашка «может устареть» с коммитами и «попросить агента обновить» |
| Стандарт | форма вместо YAML: id, заголовок, текст правила, severity, как проверяется (шаблон: файлы, mustNot/must, какие строки судить); **проверка на репозитории до сохранения** — сколько нарушений правило даёт сегодня; предупреждение для required + «все строки»; файл, который будет записан |

Навыки (чтение и правка `instructions.md`, предложения `IMPROVEMENT.md` дифом) и входящие кандидаты
(promote / reject, как `jarvis candidates`) — те же приёмы, отдельных макетов не требуют.

### 3. Черновики и коммит

- По умолчанию сохранение пишет файл в **рабочую копию** (черновик). Полоса черновиков на всех страницах
  Knowledge: что изменено, «See the diff», «Commit knowledge» — один коммит `knowledge: …` с автором —
  актором CLI (ADR-0006).
- Вариант в настройках: коммит на каждое сохранение; или ветка `knowledge/<тема>` под PR.
- После каждого сохранения индекс пересобирается для изменённых файлов: следующий прогон и «Найдёт ли
  агент?» уже видят правку.

### 4. Проверки (то, ради чего страница, а не просто редактор)

- символы и модули глоссария и `paths` документов — против графа проекта; ближайшие совпадения как
  подсказка;
- синоним в двух терминах — предупреждение (запрос раскроется в оба);
- единицы индекса документа и пустые разделы;
- стандарт — `standards.check` на всём репозитории с выбранными `lines` до записи;
- конфликт нового знания со старым — при разборе принесённого (агент сравнивает с найденными единицами).

### 5. «Принести новое» — агент разбора

Новый workflow `knowledge-intake` (один агентный шаг), запускается страницей так же, как New task
(ADR-0023 §6, п. 5): вход — текст, ссылка (MCP Atlassian, если подключён) или файл; выход — артефакт
`knowledge-proposal`: документы, термины, кандидаты в стандарты, конфликты, у каждого — evidence (цитата из
принесённого, найденные символы и единицы знания). Принесённый текст проходит редактор секретов (ADR-0010)
до модели. Принятие по пунктам пишет черновики (§3); отклонённое не теряется — остаётся в артефакте.

### 6. Устаревание и покрытие

- документ **может устареть**, если по его `paths` были коммиты после последнего коммита самого документа
  (число коммитов и что изменилось в символах — по графу);
- заготовка `generated` от onboard, которую не правил человек;
- символ глоссария, которого больше нет в графе;
- покрытие модуля: документ со `paths` на него, навык, только заготовка или ничего.

### 7. Безопасность

Те же правила, что у остального `jarvis ui` (ADR-0023 §5): только 127.0.0.1, токен сессии, `POST` с
токеном и проверкой `Origin`, всё экранируется. Запись — только под `.jarvis/knowledge`, `.jarvis/standards`,
`.jarvis/skills`; пути из `security.deniedPaths` не читаются и не пишутся; `knowledge.sources` — только чтение.

### 8. Исследование модуля (сделано)

Пересмотр объёма: правку документов, стандартов и навыков страница не делает — их пишут руками в редакторе или
модели; на странице — смотреть, добавлять термины глоссария и исследовать модули. Сделано последнее:

- **Что изучать.** Дерево модулей скана до папок внутри (в монорепо модуль — целый пакет, слишком большой для
  одного прохода), поле пути с подсказками; у узла — размер и покрытие: свой документ (`paths`), сгенерированный,
  более широкий, документация команды через `scopes`, «может устареть» (коммиты после последней правки документа).
- **Порог.** Больше 150 файлов или 15 тыс. строк — один проход описывает плохо: страница предлагает части
  (подпапки), они идут в очередь.
- **Запуск.** Тот же `jarvis onboard --module <path> [--note]` в фоне; одно исследование за раз, остальные в
  очереди. Сверка утверждений с кодом — шаг `verify` прогона `onboard-module`, поэтому прогон, продолженный
  позже (бюджет, окно квоты), сам доходит до кандидата.
- **Разбор.** Подтверждённые, отброшенные с причиной, обобщения «проверить первым» — Accept только когда все
  отмечены; Accept пишет файл черновиком в рабочую копию; файл, написанный человеком, — дифф и явный Replace
  (или другое имя), сгенерированный заменяется; Research again — новый прогон с заметкой и списком отброшенного.
- **Коммит.** Полоса незакоммиченных файлов `.jarvis/…` и Commit knowledge — один коммит с автором из git config.
- **Уведомление.** Кандидат, ждущий разбора, — в колокольчике, со ссылкой на папку.

### 9. Просмотр и глоссарий (сделано)

- Вкладки Overview, Modules, Documents, Architecture, Standards, Skills, Glossary — только чтение, у файла
  «Open in editor» и «Copy path».
- **Использование в прогонах** — из журнала: `agent.start` несёт провенанс пакета контекста
  (`knowledge:…`, `skill:…`, `standard:…`), `tool.call knowledge.read` — явный запрос по имени. Отдельного
  учёта не заводили.
- **Покрытие папки** — только документ ровно о ней (`paths` — папки одного модуля, без масок) или карта модуля
  выше; широкие документы (дизайн-система, наблюдаемость всего приложения) — «также применяется».
- **Проверка символов глоссария** — без модели: имя словом в коде (не в документах, где оно только упомянуто),
  путь — папка или файл (с корня или хвост пути; алиасы `#/`, `@/` отбрасываются), `@scope/pkg` — в
  package.json. Результат кэшируется до смены HEAD или файла глоссария.
- **Новый термин** — строка в конец таблицы в её колонках, дата сегодняшняя; термин, который уже есть, —
  отказ.

## Этапы

1. Обзор (только чтение), «Найдёт ли агент?», глоссарий с правкой и проверками, черновики и коммит.
2. Документы и стандарты (форма, проверка на репозитории), входящие кандидаты, навыки.
3. «Принести новое»: workflow `knowledge-intake`, артефакт `knowledge-proposal`, конфликты.
4. Устаревание и покрытие на обзоре, «попросить агента обновить документ».

## Открытые вопросы

- **Черновики и `jarvis apply`.** `apply` отказывается работать на «грязной» рабочей копии, а черновики
  знания делают её грязной. Варианты: предлагать закоммитить знание перед `apply`; `apply` не считает
  изменения под `.jarvis/knowledge|standards|skills` помехой; черновики хранить отдельно (stash-подобно).
- **Правка внешних источников** (`documentation/`): только чтение или правка на месте с пометкой, что это
  чужой файл.
- **Форматирование `glossary.md`.** Запись таблицы должна сохранять порядок строк и выравнивание, чтобы дифф
  в PR показывал только изменённые термины.
- **Стоимость индексации** на каждое сохранение — инкрементально по файлу; проверить на большом репозитории.
- **Файлы для «принести новое»**: какие форматы (md, txt, html; docx и pdf — через извлечение текста) и
  лимиты размера.
- **Командная работа**: страница локальная; общий процесс — через PR. Нужна ли пометка «кто последний правил
  термин» (колонка «обновлено» уже есть).

## Альтернативы

- **Править в IDE** (уже можно, `jarvis open`) — без проверок по графу, без «найдёт ли агент», без разбора
  принесённого.
- **Wiki/Confluence как источник правды** — уже поддержано через `knowledge.sources`; но правила для
  агентов (стандарты, навыки, глоссарий с символами) живут рядом с кодом и меняются вместе с ним.
- **Отдельная база знаний (БД)** — против принципа «правда — файлы в git»: теряются ревью в PR и история.
